# Delivery schedule and ownership

All times/dates use Asia/Kuala_Lumpur (MYT). This is a conditional schedule, not permission to start development. Baseline assumes POC approval by 25 October and product approval by 27 October; later approvals shift work. Total proposed technical/design effort: 30–38 focused hours, plus 3–5 teacher hours for registration, content, pilot and rehearsals. Actual data collection may require more; a bounded extension needs an explicit decision.

## Critical path and cuts

Approval → target-device capture → independent model evidence → POC decision → product approval + visual selection → four mission flows → offline integration → teacher/pilot validation → freeze → rehearsal. Registration proceeds in parallel as an owner task; it must not wait for model performance.

When one day late: remove optional glossary, animation richness and custom illustrations. When two days late: retain simple but distinct mission layouts, current-session teacher review and printable report; defer aggregation and rich export. Never cut microphone stop, uncertainty labels, learning evidence, source/mode transparency or backup verification. Fewer missions or sample-only AI requires revised scope and owner approval.

Owner checkpoints: registration/rules; POC approval; POC decision and product approval; visual selection; curriculum/content; release/deployment. Codex owns technical reports and status accuracy. Teacher owns eligibility, registration, school permissions and factual classroom evidence. No agent can assume the teacher has completed these.
