# AI SoundLab design audit - 26 October 2026

Scope: Year 4 pupil mission entry, investigation, explanation, evidence and teacher setup. Current published 0.2.3 captured with owner-approved automated Chromium because in-app capture cannot initialize. No recordings, credentials or real pupil data used. Screenshot observations are not a claim of WCAG compliance or pupil-tested comprehension.

1. Vibration entry - needs simplification. Screenshot 01-vibration-start.png accepted. Strengths: clear brand, consistent teal/amber, large touch actions, genuine ruler illustration, numbered learning stages. P1: prediction, explanation, AI and Save compete simultaneously; the first action is unclear for a child. Observation is below the first viewport while Explanation is at the top of the right column. P2: large illustration consumes much of the workspace; instructions and sentence starters repeat. Small supporting text is a readability risk requiring contrast/zoom testing. Recommend one active learning step, a compact context area, and optional writing help instead of repeated paragraphs.

2. Incomplete save - needs clearer recovery. Screenshot 02-vibration-incomplete-save.png accepted after a prediction/reason and Save. The app correctly prevents an incomplete record, but the only visible response is a generic message below the whole page in the same pale-green treatment used for status. There is no visible indication beside the missing observation/explanation. P1: replace premature Save with a contextual next-step action, and locate validation beside the required answer. Screen-reader announcement/focus behavior was not independently tested here.

3. Sound Travels investigation - working but overloaded. Screenshot 03-sound-travels.png accepted after the equal-distance run completed. Strengths: clear source/listener diagram and comparison completion indicators. P1: the actual observation question sits far below diagram, controls, timing text and a four-row millisecond table; the unrelated empty explanation remains top right. P2: timing values and rotation controls receive equal emphasis to the all-direction learning goal. Recommend prioritize all-direction evidence and nearer/later language, with model timing/advanced controls in teacher detail. Trial indicators must use text/state, not colour alone; existing text is a strength.

4. Echo pupil screen - high-priority reorganization. Screenshot 04-echo-pupil-screen.png accepted. Strengths: material selection, sound toggle and labelled original/return paths. P1: model milliseconds, distance slider and several timing/slowdown paragraphs dominate the main task of comparing reflection strength. This confirms the owner's timing complaint remains unresolved in the product. Move numeric timing and model mechanics into teacher-only detail. P1: the predefined Stronger result is visible even before a trial, which can bias a prediction. Reveal comparison outcomes after the pupil runs both trials. Keep one immediate action near the diagram and a short, explicit low-volume teaching-audio note. Screenshot does not establish audibility or timing correctness.

5. Sound Detective - functional choices need grouping. Screenshot 05-sound-detective.png accepted. Strengths: no automatic audio-identification claim, unknown source allowed, text-only AI privacy disclosure. P1: microphone, file selection, silent graph, no-microphone alternative and multiple paragraphs all precede the actual observation question. Explanation/classification can be answered in the right column before a sound is selected. P2: classification and mitigation are dense; duplicate starters add reading. Recommend choose a listening method first, then show only its relevant controls, followed by one observation prompt and later explanation. Keep privacy concise and adjacent to recording/AI actions. Actual device permissions/AI calls were not exercised in this audit.

6. Evidence Book empty state - comparatively clear. Screenshot 06-evidence-book.png accepted. Strengths: readable mission rows, honest 0/4 and no invented classroom totals. P2: all rows repeat Not saved twice, and the only large primary action is a disabled download button. Icon-only arrows do not tell a child whether they start, continue or review. Recommend a labelled Start first mission action and action labels per row, with export/cleanup grouped as secondary management. Empty-state capture does not verify saved-record persistence or deletion.

7. Teacher setup - functional, but roles could be clearer. Screenshot 07-teacher-setup.png accepted with the setup disclosure deliberately expanded; no credential was entered. Strengths: private teacher setup code is distinguished from pupil codes, replacement warning is clear, teacher mode has a different visual state. P2: configuration and pupil investigation share the same long page; teacher explanations and curriculum/model details have no dedicated home. Recommend a distinct teacher area for code setup, science notes, model timing and evidence. Keep the existing authenticated generation requirement; the demonstration toggle is not authentication. Generation/security were not tested in this visual audit.

8. Mobile Echo - readable type, excessive travel. Screenshots 08-echo-mobile-first-screen.png and 08-echo-mobile.png accepted. The first 844px screen is mainly navigation, title and context; the main task action is much farther down. The full page is approximately 3827px tall. P1: repeated scrolling separates prediction, experiment, observation and explanation. P2: horizontally scrolling mission navigation has clipped labels and no clear visible cue to hidden missions. Recommend a compact mission header, one active step and a consistent Next/Back action; do not shrink text to make everything fit. No full keyboard, screen-reader, 200% zoom or contrast-conformance claim is made.

## Overall verdict and priorities

The visual identity is coherent; the information sequence is the main problem. Preserve white/navy/teal/amber, rounded headings, existing illustrations and icons. Highest priority: one active learning task, clear next action and a dedicated teacher home for timing/model detail. Keep Echo pupils focused on comparing wall and curtain, remove millisecond return time from their main activity, and reveal conclusions after evidence. Make writing help optional, recording choices explicit, and incomplete-answer recovery local to the field. Improve empty-book actions. Preserve BM/EN, data separation, sound/microphone cleanup, secured AI, honest examples and the DSKP learning cycle.

## Limits

This run inspected current captured UI and a bounded set of interactions. It did not verify physical sound, recording permissions, actual AI feedback, credential generation, persistence/deletion, full accessibility compliance or pupil comprehension.
